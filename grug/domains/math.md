# Domain: math and CS

- State the claim exactly: assumptions, scope, and what "correct" means.
- Match rigor to consequence. Proof where a wrong answer is costly; otherwise
  types, assertions and focused tests. Tests are not proof; never call them one.
- Check small cases by running them, before and after a general argument.
- Algorithms: start with the clearest correct one. State input sizes and the
  complexity bound. Replace it only for a measured reason.
- Invariants: name them, then show each step preserves them.
- Proofs: one idea per step. Mark each step that uses an assumption. Say
  plainly when a proof is a sketch.
- Keep apart: known result (cite it), derivation (show it), conjecture (label it).
