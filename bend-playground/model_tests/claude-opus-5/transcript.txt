What I take the task to be
Three files in one directory. playground.bend prints two ASCII figures (Mandelbrot, then Sierpinski) through IO.print, and is built so the row generation forks. LAWS.bend imports it and states laws about it. PROOF.bend imports LAWS.bend and fills every law, so bend PROOF.bend reaches "All terms check." Both the run and the check must hold; a law I cannot discharge is a defect, so the laws must be chosen against what the checker can actually reduce, not against what would sound impressive.

What I read in the material that shapes the design
A few things in the pasted guide and Base drive most of the plan, and one of them contradicts the guide's prose:

"Mutual recursion is not allowed" is true of defs only. Base routinely gets mutual recursion by declaring the recursive function as a law with a function type, writing the helper that calls the law, then filling the law with a def: String.trim_start / String.trim_start.if, U32.show.go / U32.show.fin, Nat.read.go / Nat.read.if, Map.put / Map.put.bit, Word.adc / Word.adc.con. That is the standard escape hatch for "match on a computed value forces a helper, and the helper must call back". The guide's Recursion section does not mention it. I am treating Base as authoritative here, but I have designed the program so I do not need it (see below), because a law-shaped def in playground.bend is an extra thing that must be filled and an extra way for bend PROOF.bend to report an open claim.
F32 is opaque to the checker. Every F32 operation in Base is a bare law with no def - a primitive with a runtime implementation and no computational content. So no law about a Mandelbrot value is provable, ever. Anything I state must be structural.
U32 literals are a reduction risk. Base proves U32.add_comm only by matching U32{word} on variables and inducting over Word; nothing in Base ever requires a literal like 0 to unfold into a 32-deep WCon chain. So "column 0 of the Sierpinski triangle is all stars" - which needs U32.and(row, 0) == 0, i.e. Word.and(32n, word, Word.zero(32n)) == Word.zero(32n) plus literal/Word.zero convertibility - is provable if literals unfold, and unprovable if the checker keeps them native. I am not betting a deliverable on that. It stays out.
Affinity drives the signatures. Every parameter used twice needs +, including the Nat that a fork splits on, since the fork uses its predecessor three times (two recursive calls, one shift). That forces +depth: Nat, and therefore for +depth: Nat in the matching law.
Strategy
Shape of the program. Both figures are produced by the same three-layer shape, written out twice rather than once over a ~cell template (see open questions):

Mandelbrot.picture(+depth, +first_row_index) / Sierpinski.picture(...): matches depth; at 0n it emits a one-element list holding one line; at 1n+depth_pred it does a parallel let of the two half-subtrees and List.appends them.
Mandelbrot.line(width, row_index): the row followed by "\n".
Mandelbrot.row(columns_remaining, +row_index, +column_index): matches columns_remaining, emits SCon{cell, recurse} - a constructor-headed recursion over columns, flat, no helper.
Mandelbrot.cell  Mandelbrot.escape_count  Mandelbrot.shade.
main is a do IO<Unit> block with two IO.print(String.concat(...)) steps.

Fork tree. picture gives a perfectly balanced binary fork tree of depth depth, 2^depth leaves, one leaf per output row, each leaf a flat loop over width columns. Balance is structural, not hoped for: each subtree holds exactly 2^depth_pred rows. For Mandelbrot I make the per-cell work uniform too - escape_count runs a fixed iteration count and accumulates Bool.to_u32(still_inside) rather than escaping early. That satisfies Bend's second promise for a parallel call ("they run in roughly the same time") exactly rather than approximately, and it also kills the need for the law/helper mutual-recursion idiom, since the only branch left is Bool.pick, a call and not a match. The cost: every pixel pays worst-case iterations. I am taking that trade deliberately; early escape would make the left half of the image (the interior, fully iterated) and the right half (escaping in 2-3 steps) wildly unbalanced siblings, which is exactly what the fork contract asks you not to do.

The joins are List.append, which is serial and O(rows) at the root. That is the known non-ideality of this shape. The alternative - appending Strings pairwise up the tree - is O(n log n) copying, which is worse. Building the frame into an Image quadtree as the shaders guide describes is the right shape for a real renderer and the wrong one for stdout.

I am not using !. It requires a .gpu artifact beside the binary plus Metal or CUDA, and the shaders guide is explicit that allocation-heavy, list-building work belongs on the CPU pool. Parallel lets already run on every core in a compiled binary. I will say so in a comment.

Laws. Four, all structural, all provable by induction whose every reduction step is a constructor at the head - no F32, no U32 literal unfolding, no arithmetic beyond Nat.add reducing on its first argument:

Mandelbrot.row of width n has String.length == n. Induction on the width Nat. String.length only inspects the string's constructor, so the character in the head field may stay stuck forever - which is precisely why this law survives F32 being opaque. Content: the frame is rectangular no matter what the shading does.
The same for Sierpinski.row. Same proof shape, different def.
Mandelbrot.line has String.length == Nat.add(width, 1n). Needs a String.length/String.append lemma, and consumes law 1. Content: every emitted line is exactly one newline longer than the row.
List.length(Mandelbrot.picture(depth, first_row_index)) == Picture.row_count(depth), where row_count is the obvious doubling Nat. Needs a List.length/List.append lemma. Content: the fork tree emits exactly the rows it promises - each branch contributes exactly half, nothing is dropped or duplicated by the split. This is the one law that is actually about the parallelism, which is why I want it despite it being the riskiest (it forces the checker to reduce through a parallel let).
Both lemmas go in PROOF.bend as plain defs returning an equality type, oriented so that the rewrite direction is the one %e : P gives me (P marks b, the goal gets a) - so I write them as {Nat.add(len, len) == length(append(..))}, RHS-to-LHS, and never need Equal.sym.

I state row_count as Nat.add(row_count(pred), row_count(pred)) rather than Nat.double(...) specifically so the goal's right-hand side matches the append lemma's output term-for-term. Nat.double would cost me two more lemmas (add(n,n) == double(n), which itself needs add(n, 1n+m) == 1n+add(n,m)).

The induction lives in PROOF.bend-local defs; def Laws.<name>(...) just applies the local def. That way no def ever recurses on itself across a module boundary, which is the part of the cross-file law-filling story the guide does not demonstrate.

What I am deliberately not proving, and why: anything about Mandelbrot membership or escape counts (F32 is axiomatic); anything about the Sierpinski bit identity (needs U32 literal reduction); anything about the content of a character (same); total character count of a picture (needs Nat.mul distribution over the doubling - provable, but three more lemmas for no extra insight over law 4).

Adversarial pass over my own plan
Seven things I got wrong or had to change once I pushed on them:

1. Affine variables cannot be passed to + parameters. My original Mandelbrot.cell bound real_c = ... affinely and passed it to escape_count(+real_c: F32, ...). Base's precedent (Map.set.go does +ka = {key2 : String} on a variable that came out of an affine destructuring) says the promotion has to be explicit. Every such binding is now a + let. Call results passed to + parameters are fine (U32.clamp does exactly that), so only variables needed fixing. This also forced Mandelbrot.line(width, +row_index) - it hands row_index to a + parameter of row.

2. depth_pred used three times. I wanted first_row_index + 2^depth_pred for the lower half, which needs the predecessor a third time. The guide's pow2 shows a +n: Nat matched as 1n+p with p used exactly twice in a parallel call - that is my only evidence, and I did not want to extrapolate past it. So the subtree row count now rides as an explicit +half_row_count: U32 that halves by U32.shr on the way down. Rejected alternative: a +reusable = {depth_pred : Nat} let, because the termination checker reads recursive arguments syntactically ("a smaller part of its parameter, obtained through pattern matching") and a let-bound alias would likely not count.

3. The String.append lemma was avoidable, and dropping it removed a rewrite chain. Threading a line_tail: String accumulator through row makes the length law Nat.add(columns_remaining, String.length(line_tail)), which reduces by Nat.add's own first-argument match - no append lemma, no second rewrite. The line-length law then becomes a pure application of the row law with line_tail = Text.newline(), with no induction at all. That is one whole class of failure deleted.

4. Negative float literals. -2.2 may parse as an operator, and operators need spaces on both sides. Every constant is now non-negative and the offset is applied with F32.sub.

5. Early escape would have broken the fork contract, and freezing z with Bool.pick was unnecessary. Fixed iteration count stays. But I also dropped the two Bool.picks that froze z after escape: once z overflows to infinity, inf - inf is NaN and NaN < 4.0 is false under IEEE, so the accumulator stops incrementing on its own. Two fewer calls per iteration per pixel.

6. PROOF.bend must import playground.bend directly. Aliases are file-local and are not re-exported, so Laws.Playground.x does not exist. Both LAWS.bend and PROOF.bend import the program. I am inferring that a diamond import is fine; nothing in the guide says otherwise.

7. Escapes in string literals are unattested. Base never writes one. '\n' as a char literal is attested (String.lines). So the newline is SCon{'\n', SNil{}} behind Text.newline(), which also gives the line-length proof a syntactically identical term to match against.

Decisions on the open questions: 64x32 Mandelbrot and 32x32 Sierpinski; scaffolding duplicated per figure rather than templated, because I cannot confirm a law may quantify over a ~ parameter; IO.print with its trailing blank line between figures, because IO.write buys nothing here; six laws in three proof shapes.

Three chained %e : P in one body, each motive written out longhand, each relying on the checker accepting a motive that is convertible-but-not-syntactically-identical to the current goal (I write Nat.add(row_count(dp), row_count(dp)) where the goal literally says Picture.row_count(1n+depth_pred)). F32 literals 0.046875, 0.0774, 2.2, 4.0, 2.0, 0.0, 1.2. Only 1.5 is attested. If the reader wants a different form the fix is mechanical.
do IO<Unit> with a bare IO.print(..) as a non-final Unit step followed by another as the result. The guide shows a bare step (IO.sleep) and shows a final IO.print, but never the two together in one block.
A def with no parameters (Mandelbrot.width(), Text.newline()) called as f(). The guide prescribes exactly this ("a def like Screen.w()") but Base contains none, so the call syntax is unattested in code I can read.
Runtime, not the checker: the picture renders but looks wrong.
