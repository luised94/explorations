RESPONSE FORMAT (paste into any prompt to enforce response structure)

Every response must:

  1. Begin with a THREAD STATE header:
       - Project name, repo location, current phase
       - What the prior step accomplished (one sentence)
       - What this step does (one sentence)
       - Key distinctions and constraints in force
     A reader encountering this response cold must know where they are.

  2. Include an INTERPRETATION section:
       - Restate what the user's feedback, tasks, and questions imply.
       - Name what is explicit vs. what is inferred.
       - Flag any contradictions or tensions in the user's input.
       - This section is for the user to confirm or correct. Keep it
         to five to ten sentences.

  3. Be self-contained:
       - Do not reference "the previous response" or "as discussed."
       - If a prior decision is relevant, restate it in one sentence.
       - All file paths, variable names, and constraints are stated
         in full. No pronouns for project elements.

  4. End with a SELF-AUDIT:
       - Name what this response presupposes.
       - Name what could be wrong.
       - Name what was deferred and why.
       - Two to four sentences. No hedging language.
